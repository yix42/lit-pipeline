# 配方：把一份汇报/PPT 的引用反向导入 Zotero（带页码锚点）

适用场景：用户给一份 PPT/汇报/综述，要求「结合这份汇报的内容，把文献导入 Zotero」。
目标不是简单导一堆文献，而是**让每条文献能反查到汇报的具体页码**——
以后在 Zotero 里点 `PPT-P26` 就能看到「这一页的论据是哪几篇」。

首次实做：2026-09-15，王宁《全极峰值频率标测》（57 页）→ 113 条。

## 全流程（7 步）

### 1. 读 PPT，抽全文

用 `tencent-docs-routing` skill 判断路由，再走 `tencent-local-office-edit`（editor_sdk）。

```bash
# 后台打开（110 MB / 57 页的 pptx 要等）
python3 <editor_sdk 包装脚本> open_file file_path="<pptx 绝对路径>"
# 轮询直到 get_pool_status 显示 1 个 editor
# 取页数（确认 slide_count）
python3 ... slide_get_info ...
# 逐页取文本
for i in $(seq 1 57); do python3 ... slide_get_page_info ...; done
```

注意：
- macOS zsh **没有 GNU `timeout`**（`command not found: timeout`），别包 `timeout 550`，直接后台跑。
- `open_file` 默认 `open_with_existing=false` 时，**file_id 就是 file_path 字符串本身**；
  `present_files` 才会产生 UUID key。编辑工具按 `file_path` 解析，两种都能用。
- 逐页循环 57 次会超过前台超时，用后台任务 + 落盘 `/tmp/ppt_raw.txt`。

### 2. 通读全文，把「可入库的线索」分类

逐页扫一遍，把内容分成四类——这决定了后面用哪条解析路径：

| 类别 | 特征 | 处理方式 |
|---|---|---|
| **A. 页内印出的引用** | 页脚/图注有作者年份 | 按标题/作者检索，PubMed 或 CrossRef |
| **B. 汇报描述了具体研究** | 「XX 例、XX% ……」但没写出处 | 用**数字**当检索词（例数/百分比/年份区间）去 PubMed 定位 |
| **C. 只讲原理/方法** | 技术原理页，完全无出处 | 自己找**源头文献**（算法原始论文、方法学首发） |
| **D. 查不到** | 会议摘要、未见刊研究 | 走 CrossRef；实在没有就在索引文档里如实标注 |

**关键技巧：用汇报里的具体数字反查。** 例：
- P45「336 例中 8 例」→ `esearch` 命中 Kitamura 2018 Circ AE（摘要里就是 336/8）。
- P42「28 例、三种模式、三重电位」→ `"ligament of Marshall" AND tachycardia AND (28 OR "triple potential")`
  → 命中 Zhang J…Ouyang F, Heart Rhythm 2025（28 例、3 种模式、18 例三重电位）。
- P51/P52「338 例、五步法、EIVOM 18.9%」→ 命中 He/Lu 2025 JICE。

数字是最强的检索指纹，比标题词好使得多。命中后**一定要把摘要里的数字与汇报逐项对照**，
吻合才认，不吻合不要硬套。

**反例警告：不要用「装置名」当检索词。** P13 那条（108 例 / EnSite X / HD Grid / 四种标测设置）
用装置关键词搜了五轮全部落空 —— 因为论文摘要里**根本不出现这些装置名**。
换成概念词（`"peak frequency" AND voltage AND omnipolar AND gap`）一次命中，
且发现该文献**本来就在库里**，只是被当成「最接近的候选」而非「确认的出处」。

正确顺序是：
1. **先读原文**（提取 PPT 逐字文本），拿到精确数字指纹；
2. **再定检索词**：优先用论文作者会写在标题/摘要里的**概念词**（指标名、机制名、人群名），
   而不是 PPT 作者自行使用的**装置名 / 厂商名 / 软件设置名**（HD Grid、EnSite X、clique…）；
3. 命中后读全文（出版商页 / PMC），逐项比对数字与图注，确认到「连 Figure 1 的病例都对上」才算核实。

核实通过的条目打一个 `汇报出处已核实` 标签，与「我另找的旁证」在 Zotero 里明确分开，
避免日后写正文时把旁证当成原始出处引用。

### 2b. 提取 PPT 文本时要顺带看一眼「有没有印出处」

同一份汇报里，有的页页脚印了引用（好定位），有的页只描述研究不印出处（要反查），
有的页纯讲原理（要自己找源头）。**逐页扫一遍时就把这三类标出来**，
并且**把页码与页内数字原样抄下来** —— 后面反查全靠这些数字，回头再提取一次成本很高。

### 3. 分类解析元数据

```python
# A / B / C 类：PubMed 权威元数据
fetch_pubmed(pmids)      # efetch rettype=pubmed retmode=xml

# D 类（会议摘要）：PubMed 查不到，走 CrossRef
fetch_crossref(doi)      # GET https://api.crossref.org/works/{doi}
```

**先确认每条到底在哪一侧**：批量 `esearch` `"<doi>"[DOI]`，返回空 idlist 的就是会议摘要。

### 4. 组装 RIS + 定义页码锚点

每条文献配一个「标签三元组」：

```python
(pmid 或 doi, ['P26','P28'], '归类标签', '说明文字')
```

归类标签固定几个：`汇报页内引用` / `汇报原始研究` / `汇报原理支撑` / `汇报同源系列` / `会议摘要`。
再加基础标签（如 `全极峰值频率标测`）和 `PPT-Pxx` 页锚点。

### 5. 导入（第一趟）

```bash
python3 add_batchN.py --dry-run    # 先验，确认条数与元数据
python3 add_batchN.py              # 导入 + 逐条 PATCH（collections + tags + extra）
```

**必须逐条 PATCH**，不要用批量 POST（见 `pitfalls.md` 第 3 条）。

### 6. 等 1–2 分钟，跑 `--finalize`（第二趟）

```bash
python3 add_batchN.py --finalize   # 不导入，回扫集合按 DOI/标题补 tags + extra
```

这一步是必需的：第一趟写的 `extra` 会被连接器侧后续写入覆盖
（本次 13 条丢 6 条、3 条丢 3 条，`--finalize` 后 16/16 补齐）。

### 7. 生成「页 ↔ 文献」对照索引文档

`build_index_doc.py` 的模式（可直接改成自己的）：

- **直接从 Zotero 集合拉最新清单**，不要依赖可能过期的中间 json；
- 按 `PPT-` 标签分组时，**归并到「主页码」**：`P4` / `P4-P6` / `P4-P10` 都并进 `P4` 一节，
  否则各批锚点粒度不同会把同一页拆成好几节，读起来断裂；
- 章节建议：① 导入结果摘要 ② 页↔文献对照表 ③ 无标注页的补缺来源 ④ 未收口清单
  ⑤ 检索所得一览 ⑥ Zotero 使用说明 ⑦ 可复现文件清单 + 接口行为备忘；
- 无 PMID 的会议摘要，`ref()` 要输出「会议摘要 + doi」而不是 `PMID None`；
  解析 `extra` 时用 `re.match(r'PMID:\s*(\d+)')`，**匹配不到就当作无 PMID**
  （别用 `re.sub(r'^PMID:\s*', '', extra)`——会议摘要的说明文字会被当成 PMID）。

## 标签体系（本次实做，可照搬）

| 标签 | 含义 |
|---|---|
| `<主题>` | 全库基础标签，每条都有 |
| `汇报页内引用` | 幻灯片上直接印出著者 |
| `汇报原始研究` | 汇报给了研究描述，按描述定位到的原始研究 |
| `汇报原理支撑` | 汇报只讲原理、未给出处；补的是算法/量化的源头文献 |
| `汇报同源系列` | 同一研究的多场会议报告 |
| `会议摘要` | HRS/EHRA 增刊摘要，PubMed 不收录 |
| `PPT-Pxx` | 页码锚点，用于反查 |

## 收尾清单

- [ ] 集合条目数、0 重复
- [ ] 全文条目 `Extra` 全部以 `PMID:` 开头；会议摘要写 `Meeting abstract … not indexed in PubMed`
- [ ] 已逐项核实出处的条目打上 `汇报出处已核实`，与旁证区分
- [ ] 索引文档 md → docx，镜像到本地工作区并 **md5 核验**
- [ ] 未收口的条目**如实写进索引文档**，注明已试过哪些检索角度（不要静默丢弃）；
      但也要在放弃前做一次「换个检索思路」的复盘 —— 见第 6 条
- [ ] 把本次新踩的接口坑回写 `pitfalls.md`

## 第 6 条的补充：什么时候可以判定「真的找不到」

在写「未能定位」之前，先自查这四条。本次 5 条悬案里最后 1 条就是在这一步翻出来的：

1. **检索词是不是用错了维度？** 装置名 → 概念词；临床试验名 → 终点名；缩写 → 全称。
2. **是不是已经在库里了？** 前几批导入的「最接近的候选」可能其实就是正主，
   只是当时只做了模糊描述匹配，没做**逐项数字比对**。把候选的全文调出来对一遍。
3. **会议摘要查过 CrossRef 了吗？** PubMed 不收录增刊摘要（见 `pitfalls.md` 第 6 条）。
4. **换了至少 3 组不同维度的检索式吗？** 只有一组同义改写不算换思路。

四条都做过还找不到，才写「未能唯一定位」，并把试过的检索式列在索引文档里。
